# TPP Legal / Privacy / Security Release Checklist

**Status:** Mandatory pre-release gate  
**Owner:** Brau Consulting LLC  
**Baseline:** 2026-08-08

Use this checklist before a controlled pilot with real educator accounts, before general release, and after any material legal/compliance-impacting change. Record evidence links/commit SHAs/run IDs rather than relying on memory.

## A. Governance baseline

- [ ] Approved legal/compliance packet version identified by commit SHA.
- [ ] `LEGAL_COMPLIANCE_REQUIREMENTS.md` reviewed against current scope.
- [ ] No unresolved code/product behavior contradicts the packet.
- [ ] All publication blockers in `docs/legal/README.md` resolved or expressly accepted for the applicable release stage.
- [ ] Qualified legal review completed for public Terms, Privacy Policy, liability/indemnity/dispute language, and institutional agreement before those documents become effective.

## B. Data boundary

- [ ] Product scope remains adult educator/admin use only.
- [ ] No student account, roster, student identifier, grade, assessment, IEP/504, health, discipline, identifiable student work, or other student-record field exists in the release path.
- [ ] Relevant input/import/AI screens display a clear no-student-data notice.
- [ ] Browser/API/database acceptance confirms prohibited student fields are neither expected nor required.
- [ ] Support and admin procedures preserve the same boundary.

## C. Authentication and authorization

- [ ] Approved users authenticate successfully.
- [ ] Unapproved users are denied.
- [ ] Individual accounts cannot obtain another user's planning data.
- [ ] Cross-organization/school access is denied except where an approved role explicitly permits it.
- [ ] Admin roles expose only approved professional data.
- [ ] Elevated database/service-role credentials are absent from browser bundles/network responses.
- [ ] Secrets are absent from source and logs.

## D. AI boundary and controls

- [ ] Production AI provider/account/model identified.
- [ ] Provider's current business terms/DPA/data-use posture reverified.
- [ ] Production account is confirmed not opted into customer-content model training unless separately approved and disclosed.
- [ ] AI requests contain only permitted professional planning context.
- [ ] Test confirms no student data, credentials, or unrelated customer data is sent.
- [ ] Teacher review/accept/edit/reject controls work for material AI suggestions.
- [ ] AI errors do not corrupt saved planning data.
- [ ] Manual planning remains usable during AI failure where intended.
- [ ] AI operational logs contain bounded metadata and no secrets.

## E. Standards integrity

- [ ] Authoritative standard text is ingested deterministically, not generated by AI.
- [ ] Source/version/effective-period provenance is present.
- [ ] AI interpretation is visibly distinguishable from source text.
- [ ] Course mapping prevents unrelated standards leakage.
- [ ] Source-change reconciliation does not silently replace approved source text.
- [ ] Historical saved plans retain applicable source/snapshot context.
- [ ] Scheduled and event-driven source-reconciliation controls required by the current standards governance are tested.

## F. Privacy inventory

- [ ] Data inventory reflects every current input, database table, log, export, AI request, support path, and admin report.
- [ ] Privacy Policy categories match the inventory.
- [ ] No analytics/session replay/advertising technology exists unless disclosed and approved.
- [ ] Cookies/local storage/session mechanisms inventoried.
- [ ] Sale/advertising statements remain accurate.

## G. Subprocessors

- [ ] AWS services/Region verified.
- [ ] Supabase project Region, enabled services, backup behavior, DPA/security posture verified.
- [ ] OpenAI production terms, DPA/data-use posture, and account setting verified.
- [ ] Any DNS, email, support, monitoring, analytics, payment, or other provider that routinely processes customer/account data evaluated and listed if material.
- [ ] Subprocessor List matches deployed reality.

## H. Logging, retention, and deletion

- [ ] AWS application-log retention verified (current pilot target: 30 days).
- [ ] Authentication/security log retention documented.
- [ ] AI metadata retention documented.
- [ ] Database active-content retention approved.
- [ ] Audit/version-history retention approved.
- [ ] Database backup retention/cycling documented.
- [ ] Generated-export server-side retention verified (prefer transient if feasible).
- [ ] Account/institution termination export window approved.
- [ ] Active deletion tested.
- [ ] Backup restoration process prevents silent resurrection of deleted records into active use.
- [ ] Public deletion language matches tested capability.

## I. Security and infrastructure

- [ ] HTTPS/TLS active on public application hostname.
- [ ] Certificate/hostname validation passes.
- [ ] Least-privilege runtime/deployment roles reviewed.
- [ ] Secrets delivered only through approved protected paths.
- [ ] Container/image provenance recorded and immutable image deployed.
- [ ] Database RLS/authorization controls reviewed/tested.
- [ ] Logs checked for tokens, secrets, student data, and sensitive stack traces.
- [ ] Rollback path tested/verified for the release mechanism.

## J. Incident readiness

- [ ] Primary incident lead designated.
- [ ] Alternate incident contact designated.
- [ ] Security/support contact channel operational.
- [ ] Incident record template available.
- [ ] Credential-exposure procedure tested/tabletopped.
- [ ] Cross-account authorization incident tabletop completed.
- [ ] Accidental student-data-to-AI scenario tabletop completed.
- [ ] Provider incident/outage escalation path documented.
- [ ] Alabama breach-law legal review trigger understood.

## K. Accessibility

- [ ] Core teacher workflow keyboard-only test passes.
- [ ] Core admin workflow keyboard-only test passes.
- [ ] Focus order and visible focus checked.
- [ ] Accessible names/labels checked.
- [ ] Required-field and error messaging checked.
- [ ] Contrast checked for core UI.
- [ ] Zoom/reflow checked.
- [ ] Representative screen-reader pass completed.
- [ ] Export accessibility claims limited to tested capability.
- [ ] Accessibility statement wording matches evidence.

## L. Terms and institutional contracting

- [ ] Brau Consulting LLC legal name correct everywhere.
- [ ] Public mailing address approved.
- [ ] Legal/support/privacy/security email addresses operational and approved.
- [ ] Effective dates set.
- [ ] Fees/payment/renewal terms match actual offering.
- [ ] Post-termination/export/delete terms match implementation.
- [ ] Governing law, venue, dispute process, indemnity, and liability language approved by counsel.
- [ ] Public-school/governmental contracting restrictions accounted for in institutional form.

## M. UI/legal publication

- [ ] Terms link present where required.
- [ ] Privacy Policy link present.
- [ ] AUP/AI Notice accessible from appropriate help/legal surface.
- [ ] No-student-data notice appears at high-risk input/AI/import points.
- [ ] Version/effective date recorded for published Terms and Privacy Policy.
- [ ] Historical published versions retained.
- [ ] Acceptance/consent event captured if legal review determines affirmative acceptance is required for the release model.

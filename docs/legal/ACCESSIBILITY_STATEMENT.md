# Teacher Planning Platform — Accessibility Statement

**Provider:** Brau Consulting LLC  
**Status:** Pre-Release Draft — Not Yet Effective

Brau Consulting LLC is committed to making Teacher Planning Platform (TPP) usable by educators and administrators with disabilities.

## Our approach

TPP should be designed and maintained with accessibility considered throughout product development rather than treated only as a post-release remediation task. Relevant development practices include semantic structure, keyboard-operable controls, visible focus states, meaningful labels, sufficient contrast, understandable error messaging, text alternatives for meaningful non-text content, and compatibility with common assistive technologies where reasonably achievable.

## Standards target

The pre-release engineering target is substantial conformance with WCAG 2.2 Level AA for the TPP web application and core user workflows. This statement does not represent that an independent accessibility audit has already certified full conformance.

**Release requirement:** Core teacher and administrator workflows must be tested for keyboard operation, focus order, accessible naming, contrast, zoom/reflow, validation/error behavior, and representative screen-reader use before this statement is published as an effective accessibility claim.

## Documents and exports

TPP may generate or populate PDF and other planning documents. Accessibility of an exported document can depend on the source template, export technology, content entered by the educator, and downstream software. Brau Consulting will document known limitations and should not describe generated PDFs as fully accessible unless the specific export path has been tested for that claim.

## Feedback and accommodation

If you encounter an accessibility barrier in TPP, contact Brau Consulting and describe the affected page or workflow, the barrier encountered, and any assistive technology involved if you are comfortable providing that information. Brau Consulting will use the report to evaluate reasonable remediation.

## Continuous improvement

Accessibility requirements apply to new features and material UI changes. Accessibility defects affecting core workflows should be tracked and prioritized as product-quality issues.

## Review cadence

Review this statement and the application's accessibility evidence before general release, after major redesigns, and at least annually thereafter.
